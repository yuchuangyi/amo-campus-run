# 使用说明

> 以 **8.7.7** 版本为例。别的版本把命令里的 `8.7.7` 换成对应数字就行，参数完全一样。

---

## 先搞清楚一件事

**这个工具在电脑上跑，手机不需要装任何东西，也不需要 root、不需要改 App。**

你只需要在手机上做一件小事：**看一眼 App 的版本号**（下面有图解步骤）。

```
手机：查版本号 ──→ 电脑：装环境 ──→ 电脑：登录 ──→ 电脑：跑 ──→ 电脑：看结果
```

## 准备工作（只做一次）

### 第 1 步｜手机上查 App 版本号

打开手机上的目标 App，进 **「我的」→ 设置 → 关于我们 / 关于 App**，能看到类似 `8.7.7` 的数字。

> 不同版本菜单位置可能不一样。找不到就在「我的」页面里翻一翻，或者看 App 商店页面的"版本信息"。
>
> **记下这个数字**，后面选目录要用。仓库里现在有 `8.7.2`、`8.7.4`、`8.7.7`、`8.7.9` 四个目录，选和你手机上一模一样的那个。找不到完全一样的，选**小于等于**你版本号里最大的那个。

### 第 2 步｜电脑上装 Python

1. 打开 <https://www.python.org/downloads/>，下载最新的 Python（3.9 以上都行）
2. 安装时**务必勾选最下面那个 `Add Python to PATH`**
3. 装完验证：按 `Win + R`，输入 `cmd` 回车，在黑窗口里敲：

```bash
python --version
```

能看到 `Python 3.11.x` 之类的就行。

### 第 3 步｜把项目下载到电脑

**方式 A（推荐）**：网页上点绿色 `Code` 按钮 → `Download ZIP` → 解压到一个**路径里没有中文和空格**的目录，比如 `D:\campus-run`。

**方式 B（会用 git 的话）**：

```bash
git clone https://github.com/yuchuangyi/amo-campus-run.git
```

### 第 4 步｜装依赖

打开命令行，进到项目里的版本目录，装两个包：

```bash
cd D:\campus-run\src\8.7.7
pip install -r requirements.txt
```

> 卡住不动就换国内源：
> `pip install -r requirements.txt -i https://mirrors.cloud.tencent.com/pypi/simple`

看到 `Successfully installed pycryptodome-... requests-...` 就成功了。

## 三分钟跑通第一次

> **下面所有命令都要先 `cd` 进版本目录再执行**，不然会报"找不到模块"。
>
> ```bash
> cd D:\campus-run\src\8.7.7
> ```

### 第 1 步｜登录

```bash
python login_cli.py -u 你的手机号 -p 你的密码
```

**你会看到**（成功时）：

```
[✓] 账号登录
[✓] 前置检查
[✓] 人机校验        触发滑块
    偏移量: 87.34px
[✓] 凭证核验
    用户ID: 1234567   姓名: 张*   学校: xx大学
```

看到姓名和学校说明登录成功，凭证已经存到 `session.json` 里，**下次不用再登录**。

> - 中途出现"人机校验 触发滑块"是正常的，脚本会自己识别拼图缺口，等两三秒就好。
> - 如果连续失败，换个时间再试，同一号码短时间请求太频繁会被加强校验。
> - 成功一次之后，之后的命令都不用带账号密码了。

### 第 2 步｜看一眼学校的跑步规则

```bash
python policy_cli.py
```

**你会看到**学校的学期目标、单次有效里程范围、配速上下限，每个围栏的编号和中心坐标，以及**有没有启用人脸认证**。

这一步不是必须的，但**强烈建议第一次先跑**：

- 知道学校要求的最短里程（有的学校 1.5km 以下不算）
- 知道配速限制（太快会被判异常）
- 拿到围栏编号和中心坐标（万一自动获取失败，可以手动填）
- **确认人脸认证是不是"启用"** —— 如果启用了，跑完可能要在 App 里刷脸，这一点脚本帮不了你（见文末常见问题）

### 第 3 步｜试跑一次，不联网

```bash
python run_cli.py --dry-run -d 2000 -p 360 --dump traj.json
```

**这一步只算数据，不碰服务器，绝对安全，可以随便试。**

**你会看到**：

```
[✓] 轨迹数据生成
    目标里程: 2000m   配速: 360s/km   预计用时: 720s
    步数: 1873        步幅: 1.07m
    打卡点: 3/3
[✓] 数据落盘        traj.json
```

参数含义：

- `-d 2000` = 跑 2 公里
- `-p 360` = 每公里 6 分钟（`300` 是 5 分钟，`420` 是 7 分钟，自己调）

跑完打开 `traj.json`，能看到完整轨迹数据。**数据看着合理再往下走。**

### 第 4 步｜正式跑

```bash
python run_cli.py -d 2000 -p 360 --verify
```

**注意：这次没有 `--dry-run`，会真的和服务器交互，产生一条真实的跑步记录。**

**你会看到**：

```
[✓] 载入会话          传输模式: direct   设备机型: Android|GenericDevice
[✓] 自动获取打卡点    3 个
[✓] 发起阳光跑起跑
    跑单编号: RUN20261029xxxxx
[✓] 轨迹上传 第 1/8 块
[✓] 轨迹上传 第 2/8 块
...
[✓] 打卡点上传        3/3
[✓] 提交阳光跑结算
    里程: 2000m   用时: 720s
[✓] 结算成功
```

整个过程大约 10~20 秒（8 个分块，每块间隔 1.5 秒）。

### 第 5 步｜确认结果

```bash
python history_cli.py -t sun -s 5
```

能看到刚才那单排在第一条。

想看这一单有没有被判异常，查详情：

```bash
python history_cli.py --detail RUN20261029xxxxx
```

（把 `RUN20261029xxxxx` 换成上面拿到的跑单编号）

会打印轨迹、配速曲线、步频，以及**服务端的判定结果**。没看到"异常"标记，就算成功了。

## 手机上还要做什么

### 场景一：只是想跑一次 → 手机上不用做任何事

按上面五步操作就行。手机唯一的作用是**查版本号**。

### 场景二：想用 USB 连接模式（adb 传输）

有些情况下需要让请求从手机发出（出口 IP 和手机一致）。这时要在手机上开 USB 调试：

**Android 手机开 USB 调试：**

1. 手机 **设置 → 关于手机**
2. 连续点击 **「版本号」** 7 次，直到提示"您已处于开发者模式"
3. 返回设置，找到 **「开发者选项」**（有的手机在「系统」里）
4. 打开 **「USB 调试」**
5. 用数据线连电脑，手机弹出"是否允许 USB 调试"→ 点**允许**（勾选"一律允许"）

**电脑上验证手机连上了**：

```bash
adb devices
```

能列出一串设备号就说明通了。然后跑命令时加参数：

```bash
python run_cli.py -d 2000 -p 360 --transport adb
```

> 电脑上没装 adb？下载 [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools) 解压，然后把那个文件夹加进系统 PATH，或者用 `--adb-path "D:/platform-tools/adb.exe"` 指定路径。

### 场景三：登录老是被滑块卡住 → 手机上抓 token

如果账号怎么都登不上，可以让手机抓一次包，把 token 拿给电脑用。

1. 手机连上和电脑**同一个 WiFi**
2. 电脑装 [mitmproxy](https://mitmproxy.org/)，命令行跑 `mitmproxy`（默认监听 8080 端口）
3. 手机 WiFi 设置里，把**代理**改成「手动」，主机名填电脑的局域网 IP，端口填 `8080`
4. 手机浏览器打开 `http://mitm.it`，装 Android 证书
5. 手机上正常打开 App 登录一次
6. 回到电脑的 mitmproxy 界面，找 `api.huachenjie.com` 的请求，看请求头里的 `token` 和 `saToken`
7. 把拿到的值注入电脑：

```bash
python login_cli.py --token 你抓到的token --satoken 你抓到的saToken
```

> 这条路比较折腾，**只在登录实在搞不定时才用**。正常情况第 1 步的密码登录就够。

### 场景四：能不能直接在手机上跑？

技术上可以（装 Termux + Python + 依赖），但：

- 要手动编译 `pycryptodome`，容易失败
- 手机上敲命令比电脑难受得多
- 出问题不好排查

**不推荐**。这个工具本来就是电脑上用的。

## 坐标不用自己找

很多人卡在"`--lat` / `--lng` 到底填多少"。**其实大部分情况根本不用填。**

### 方法一：什么都不填（推荐）

```bash
python run_cli.py -d 2000 -p 360
```

程序会自己：

1. 调学校的围栏接口，拿到所有打卡点
2. 自动用**第一个打卡点**作为起跑位置
3. 规划一条串联打卡点的路线

只要你们学校在系统里配了围栏（绝大多数都配了），这条命令就能直接跑通。

### 方法二：从规则里抄

先跑 `python policy_cli.py`，输出里会列出打卡点的坐标，直接抄一个填进去：

```bash
python run_cli.py -d 2000 -p 360 --lat 36.6512 --lng 117.1201
```

### 方法三：地图上取点

1. 打开 [高德地图坐标拾取](https://lbs.amap.com/tools/picker) 或百度地图拾取坐标网站
2. 搜你学校，点一下操场位置
3. 复制显示的经纬度填进去

> ⚠️ 一定用**高德/百度（GCJ-02 / BD-09）坐标**，别用 Google 地图的 WGS-84，差几百米可能落到围栏外面。

### 什么时候必须填坐标

- 学校没配电子围栏
- 你想指定某条特定路线（比如就想在田径场跑）
- 程序报错「缺少起跑坐标」

## 参数速查

### 跑步最常用的 3 个

| 参数 | 意思 | 举例 |
|:---|:---|:---|
| `-d 2000` | 跑多少**米** | `-d 3000` = 3 公里 |
| `-p 360` | 每公里多少**秒** | `300`=5分/km、`360`=6分/km、`420`=7分/km |
| `--dry-run` | 只算不跑 | 试参数时必加 |

### 一般不用改的

| 参数 | 默认 | 什么时候改 |
|:---|:---|:---|
| `-t sun` | 阳光跑 | 改成 `free` 是自由跑（不需要打卡点） |
| `--shape` | 自动 | 想指定轨迹形状：`track` 跑道、`loop` 环线、`grid` 街区 |
| `--seed` | 随机 | 想复现同一条轨迹时用，填同一个数字 |
| `--auto-fence` | 关 | 自动拉打卡点，一般不用加（默认就会拉） |
| `--verify` | 关 | 结算后自动回查结果，建议加 |

### 上传节奏（卡住或被限流才调）

| 参数 | 默认 | 说明 |
|:---|:---|:---|
| `--chunk-delay 1.5` | 1.5 秒 | 分块之间的间隔，**被提示请求太快就加到 3** |
| `--chunk-seconds 90` | 90 秒 | 每块管多长的轨迹，一般不用动 |

### 传输模式

| 参数 | 什么时候用 |
|:---|:---|
| 不加（默认 direct） | 绝大多数情况 |
| `--transport adb` | 需要请求从手机发出 |
| `--transport proxy --proxy http://127.0.0.1:7890` | 电脑开着代理软件时**必须加**，否则连不上 |

## 出问题看这里

<details>
<summary><b>报「找不到模块 client」/「ModuleNotFoundError」</b></summary>

没进对目录。必须先：

```bash
cd D:\campus-run\src\8.7.7
```

然后再执行 `python xxx_cli.py`。每个版本目录是独立的。
</details>

<details>
<summary><b>报「缺少起跑坐标」</b></summary>

说明你们学校没配围栏，或者接口没返回数据。手动填一个坐标：

```bash
python run_cli.py -d 2000 -p 360 --lat 36.6512 --lng 117.1201
```

坐标怎么来见[上一节](#坐标不用自己找)。
</details>

<details>
<summary><b>所有请求都失败 / 连接被拒</b></summary>

**八成是代理软件的锅。** 脚本故意忽略系统代理（避免 Clash 关闭后残留的代理变量导致连不上）。

开着代理软件的话，两个选择：

```bash
# 1. 关掉代理软件再跑
# 2. 或者显式告诉脚本走代理
python run_cli.py -d 2000 -p 360 --transport proxy --proxy http://127.0.0.1:7890
```
</details>

<details>
<summary><b>登录一直卡在滑块验证</b></summary>

- 等几分钟再试，短时间请求太频繁会被加强校验
- 换个网络环境（手机热点）
- 实在不行走[抓 token](#场景三登录老是被滑块卡住--手机上抓-token)
</details>

<details>
<summary><b>跑完了但里程被扣 / 显示异常</b></summary>

先查原因：

```bash
python history_cli.py --detail 你的跑单编号
```

常见原因和解决办法：

| 现象 | 原因 | 怎么改 |
|:---|:---|:---|
| 里程被扣一部分 | 配速超出学校范围 | 调 `-p`，先看 `policy_cli.py` 的配速限制 |
| 标记"轨迹异常" | 轨迹点跳变太大 | 换 `--shape loop` 或 `--shape track` |
| 标记"步频异常" | 步数配速不匹配 | 换 `-p` 值，一般 330~420 最安全 |
| 打卡点没通过 | 路线没串够点 | 加 `--auto-fence`，或手动 `--fence` 指定 |
</details>

<details>
<summary><b>提示「未找到 adb」</b></summary>

只有在用 `--transport adb` 时才会遇到。三选一：

```bash
# 1. 装 Platform Tools 并加进 PATH
# 2. 直接指定路径
python run_cli.py -d 2000 -p 360 --transport adb --adb-path "D:/platform-tools/adb.exe"
# 3. 设环境变量
set ADB_PATH=D:\platform-tools\adb.exe
```
</details>

<details>
<summary><b>学校开了人脸认证怎么办</b></summary>

`python policy_cli.py` 的输出里有「人脸认证: 启用 / 关闭」。

如果是**启用**，说明你们学校要求跑步过程中或结算时刷脸核验。脚本不含任何人脸绕过能力，也没有这个打算 —— 这种情况只能在 App 里正常刷脸。

脚本能做的仍然是把轨迹和里程数据准备到位，刷脸那一步你自己完成。
</details>

<details>
<summary><b>报签名错误 / 接口 404</b></summary>

App 版本和目录对不上。重新确认手机上的版本号，用对应目录。如果 App 刚更新、仓库里还没有对应版本，那就是还没适配，只能等。
</details>

<details>
<summary><b>session.json 能发给别人吗</b></summary>

**绝对不能。** 里面是你的登录凭证，等于账号密码。`.gitignore` 已经排除它，但你自己别手动 `git add -f` 提交。
</details>

## 完整命令一览

```bash
# ── 一次性准备 ──────────────────────────────
cd D:\campus-run\src\8.7.7
pip install -r requirements.txt

# ── 登录（只需一次）──────────────────────────
python login_cli.py -u 手机号 -p 密码

# ── 查信息 ────────────────────────────────
python policy_cli.py                # 学校规则 + 打卡点坐标
python user_cli.py                  # 个人档案
python score_cli.py                 # 跑步成绩
python history_cli.py               # 跑步历史
python history_cli.py --detail 编号  # 单次详情 + 判定结果
python rank_cli.py                  # 排行榜

# ── 跑步 ─────────────────────────────────
python run_cli.py --dry-run -d 2000 -p 360 --dump traj.json   # 试算，不联网
python run_cli.py -d 2000 -p 360 --verify                     # 正式跑
python run_cli.py -t free -d 2000 -p 360                      # 自由跑

# ── 排查 ─────────────────────────────────
python risk_probe.py --config-only              # 只读判定规则
python risk_probe.py --detail 编号              # 分析某单被判在哪
python traj_selftest.py                         # 轨迹算法自检
```
